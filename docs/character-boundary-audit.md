## 检查方法与消费时机

逐个检查九个可选角色的旗舰/副舰入口，并追踪伴随舰、支援弹体、舞台受影响者：创建与派生属性 → 输入与支付 → 状态生效 → 移动/接触/攻击 → 净化/死亡/转队 → 快照与 AI/显示消费。检查实际字段的写入点和顺序，不只检查循环导入。

- **角色能力**：解释具体角色状态，供移动、回能、攻击、碰撞等流程只读查询；读取不得过期清理、扣费或推进状态。
- **角色效果**：在确定的权威阶段同步提交。基础伤害后立即处理命中效果；冲撞能力消费成功后才破盾；同 tick 刚生效的技能仍保留净化保护。
- **领域实体**：持有并提交生命、资源、位移、冷却、集合归属等基础状态。角色效果通过领域操作改变这些状态。
- **投影**：将权威状态转为角色摘要与协议字段，不参与战斗推进。字段名可以包含角色语义；底层移动和弹体命中流程不应据此识别角色。

不是把所有状态延后到帧末统一消费。现有规则依赖即时结算及确定顺序，改变消费时机可能改变开火资格、后续碰撞、护盾次数和胜负。

### 保留的领域引用为何仍合理

- `rules/*-port.js` 是本游戏的权威适配层，可读取实时领域对象并调用所有者操作；向新抽出的旗舰、形态、光线、赞助生命周期及纯阶段提供受限操作。AI 策略与页面只消费观测/投影。旧角色运行时中承担权威适配的部分仍可取得领域对象，不把它们宣称为全部只接收 DTO 的纯组件。
- 护盾、光球、雷达、猫爪和猎杀的旧组件对象仍在可信规则层可见，但实际写入归各自生命周期模块；几何、能力与序列化查询不负责清理或续期。当前没有为了消除所有实体参数而加一层同等权限的空包装。
- 角色对舰船的基础状态改变经位移、档位、控制、资源、命中、转队及退场操作提交；对局集合由创建/退场入口维护。复查了角色模块中的基础字段赋值、效果/冷却写入、集合追加和属性重定义，再核对对应调用链。检索本身不是所有权证明，也不等于这些 JavaScript 对象在语言层全部不可写。
- 角色逻辑抽取和功能门禁不会自动消除只读投影/冻结的成本。用户最新要求接受少量开销、优先设计边界；保留性能观测，不以恢复原始耗时为重构目标。物理设备、真实远程延迟和人工对战感受仍未覆盖。
