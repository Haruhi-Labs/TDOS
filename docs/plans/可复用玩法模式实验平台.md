# TDOS 可复用玩法模式实验平台执行文档

## 一、任务背景

目标仓库：

```text
https://github.com/feiniao87968492/TDOS
```

当前开发基线：

```text
feature/2v2-online-mode
```

项目目前包含：

```text
/play      正式单人模式
/online    在线模式
/debug     AI 推演与调试
```

接下来需要持续开发新的玩法模式，未来可能包括：

```text
标准歼灭
占领战区
护送目标
生存模式
Boss战
资源争夺
限时得分
其他实验模式
```

由于现有正式模式较多，不能每次同时修改：

```text
单人
在线1v1
在线2v2
AI房
观战
服务端
调试页
```

因此，本任务不是建立一个一次性的 AI 1v1 页面，而是建立一个：

```text
可重复使用的玩法模式实验平台
```

建议路由：

```text
/prototype
```

AI 1v1 只是该平台的第一个测试运行环境，不是平台本身。

# 二、最终目标

建立以下架构：

```text
/prototype
    │
    ├─ 模式选择器
    ├─ 通用对局设置
    ├─ 模式参数面板
    ├─ 暂停 / 单步 / 倍速
    ├─ 诊断面板
    └─ 本地比赛运行器
              │
              ▼
        Mode Definition
              │
              ▼
        MatchSimulation
              │
              ▼
         共享玩法核心
```

后续增加一个新模式时，应尽量只需要：

```text
新增模式定义文件
注册模式
添加对应共享模式规则
添加模式专项测试
```

不应重复修改整个原型平台。

# 三、最高优先级验收原则

## 3.1 新增第二个模式时不得修改平台核心

本任务最重要的验收标准：

> 新增第二个实验模式时，不需要修改 prototype 平台的主要运行逻辑。

新增模式允许：

```text
新增 src/prototype/modes/example-mode.js
新增 shared/modes/example-mode.js
在集中注册表中增加一项注册
新增测试
```

正常情况下不应修改：

```text
src/prototype/index.js
src/prototype/runtime.js
src/prototype/parameter-panel.js
src/prototype/diagnostics.js
src/battle/render.js
src/solo.js
src/online.js
server/server.js
```

如果新增第二个模式必须在 `prototype/index.js` 中增加大量：

```js
if (modeId === "xxx") {
  // 模式专属处理
}
```

说明平台设计失败，不得退出 `/loop`。

---

## 3.2 原型页面不包含具体模式规则

禁止在原型平台核心文件中直接编写：

```text
占点积分计算
护送目标移动
Boss阶段切换
生存波次生成
特定模式胜负判断
```

这些规则必须放在模式定义或共享模式模块中。

---

## 3.3 不复制现有游戏核心

禁止复制：

```text
shared/game-core.js
MatchSimulation
CHARACTER_DEFS
src/solo.js
src/battle/render.js
src/battle/template.js
```

禁止新增：

```text
prototype-game-core.js
prototype-match-simulation.js
prototype-character-defs.js
prototype-render.js
```

正确结构：

```text
prototype platform
       │
       ▼
共享 MatchSimulation
       │
       ▼
共享 gameplay 和 mode rules
```

# 十、阶段三：模式注册器

新增：

```text
src/prototype/registry.js
```

建议接口：

```js
const modes = new Map();

export function registerPrototypeMode(mode) {
  validateModeDefinition(mode);

  if (modes.has(mode.id)) {
    throw new Error(`Duplicate mode id: ${mode.id}`);
  }

  modes.set(mode.id, mode);
}

export function getPrototypeMode(id) {
  return modes.get(id) || null;
}

export function listPrototypeModes() {
  return [...modes.values()];
}
```

注册行为必须：

```text
阻止重复id
阻止非法模式
保持注册顺序
允许获取单个模式
允许列出全部模式
```

不要在 `index.js` 中手写巨大的模式数组。

可以增加集中注册文件：

```text
src/prototype/modes/index.js
```

示例：

```js
import { registerPrototypeMode } from "../registry.js";
import { standardAiOneVsOne } from "./standard-ai-1v1.js";
import { validationMode } from "./validation-mode.js";

export function registerBuiltInPrototypeModes() {
  registerPrototypeMode(standardAiOneVsOne);
  registerPrototypeMode(validationMode);
}
```

# 十二、运行时更新顺序

每个固定 Tick 建议按以下顺序执行：

```text
1. 处理玩家输入
2. 推进 MatchSimulation
3. 序列化或读取必要状态
4. 调用 modeDefinition.updateModeState
5. 调用 modeDefinition.resolveOutcome
6. 更新诊断信息
7. 如产生结果，停止规则推进
```

示例：

```js
function stepFixedTick(dt) {
  simulation.update(dt);

  const snapshot = simulation.serializeState();

  modeState = modeDefinition.updateModeState({
    simulation,
    snapshot,
    modeState,
    parameters: modeParameters,
    dt,
  });

  result = modeDefinition.resolveOutcome({
    simulation,
    snapshot,
    modeState,
    parameters: modeParameters,
  });
}
```

不要让页面直接调用具体模式函数。

# 十三、MatchSimulation 与模式结果关系

当前 `MatchSimulation` 可能已经内置标准歼灭胜负逻辑。

本轮不要立即彻底重写所有胜负体系。

采用兼容方式：

```text
标准歼灭模式
→ 可以继续使用 MatchSimulation 当前 phase 和 winner

实验模式
→ 可通过外部 modeDefinition 维护附加目标和附加结果
```

建议结果结构：

```js
{
  finished: true,
  winnerAllianceId: "A",
  winnerSeat: null,
  reason: "score_limit",
  label: "A阵营达到目标积分",
}
```

必须避免实验模式直接修改页面 DOM 来宣布胜负。

结果必须从 runtime 输出。


建议：

```js
accumulator += frameDelta * speedScale;

}
```

限制单帧最大循环次数，避免切回页面时卡死。

# 二十一、模式状态隔离

每次开始或重开时必须调用：

```js

```

不得复用上一局的模式状态。

切换模式时必须清理：

```text
旧 simulation
```
