# 二、任务目标

在现有可复用 Prototype Mode Lab 中实现一个新的资源争夺玩法。

该模式用于解决：

```text
标准歼灭战通常1～2分钟结束
对局过早进入正面决战
地图缺少持续争夺目标
局内变化和随机性不足
战术选择不足
一方遭受早期损失后难以翻盘
```

新玩法核心：

```text
随机地图布局
+ 随机移动地形
+ 区域控制
+ 战争点数
+ 资源包
+ 主动战术技能包
+ 舰船复活
+ 人机目标决策
```

最终正式规模：

```text
3名玩家 vs 3名玩家
```

按照当前 TDOS 的控制结构，最终定义为：

```text
A阵营：A1、A2、A3
B阵营：B1、B2、B3

每名玩家控制1支三舰编队
最终为6支编队、18艘基础舰船
```

本轮不立即开发六人联网。

先在 Prototype 中依次完成：

```text
规则单测
→ 1v1人机验证
→ AI vs AI批量验证
→ 3v3规模人机验证
```

# 五、当前结构的已知限制

## 5.1 Runtime 仍固定为 A/B

当前 Runtime 只支持：

```text
teamLoadouts.A
teamLoadouts.B
controlA
controlB
```

第一阶段允许继续用该结构开发新模式。

但最终3v3规模验证前，必须改造为：

```text
可配置舰队席位
可配置阵营
可配置控制者
可配置本地席位
```

## 5.2 页面阵容配置仍固定为 A/B

当前 Prototype 页面只显示：

```text
A队阵容
B队阵容
```

第一阶段不需要马上修改。

3v3阶段再改成根据 Runtime Preset 动态生成：

```text
A1
A2
A3
B1
B2
B3
```

## 5.3 Runtime 缺少模式动作接口

当前：

```js
runtime.applyAction(action, seat)
```

会直接调用：

```js
simulation.applyActionForSeat(seat, action)
```

新模式需要处理：

```text
使用战术技能
选择技能目标
拾取资源
调试生成资源
调试切换区域
```

因此需要增加通用的模式动作拦截接口，不能在 Prototype 页面按模式 ID 判断。

## 5.4 缺少模式表现扩展接口

当前 Prototype 只调用共享：

```text
drawBattleWorld
drawMinimap
```

新模式需要绘制：

```text
地形
控制区
资源包
技能包
技能效果
复活效果
战争点数HUD
```

必须增加通用的 Presentation 扩展能力。

不得在 `src/prototype/index.js` 中硬编码：

```js
if (mode.id === "stellar-territory") {
  // 绘制地形
}
```

# 八、扩展 Mode Definition

现有必需接口继续保留：

```js
createInitialModeState
updateModeState
resolveOutcome
buildDiagnostics
serializeModeState
```

增加以下可选通用接口。

## 8.1 beforeSimulationStep

```js
beforeSimulationStep({
  simulation,
  snapshot,
  modeState,
  parameters,
  dt,
  runtime,
})
```

用途：

```text
计算地形环境倍率
准备本Tick临时状态
清除上Tick环境修正
处理即将到期的状态
```

## 8.2 handleAction

```js
handleAction({
  action,
  seat,
  simulation,
  snapshot,
  modeState,
  parameters,
  runtime,
})
```

返回：

```js
{
  handled: true,
  accepted: true,
  modeState,
  events,
}
```

未处理普通战斗动作时：

```js
{
  handled: false,
}
```

Runtime 再把动作交给：

```js
simulation.applyActionForSeat()
```

## 8.3 getPresentationState

```js
getPresentationState({
  snapshot,
  modeState,
  parameters,
})
```

只返回可序列化数据。

不得返回 Canvas、DOM 或函数。

## 8.4 createPresentation

该接口放在 Prototype 模式预设中，而不是共享规则中：

```js
presentationFactory({
  canvas,
  root,
  quality,
  reducedMotion,
})
```

返回：

```js
{
  sync,
  update,
  renderWorldBefore,
  renderWorldAfter,
  renderScreen,
  destroy,
}
```

Prototype 核心只调用接口，不理解具体模式。




# 十、随机数系统

当前 Runtime 虽然保存 `randomSeed`，但新模式必须真正使用确定性随机数。

新增：

```text
shared/gameplay/seeded-rng.js
```

建议接口：

```js
createSeededRng(seed)
```

返回：

```js
next()
nextInt(min, max)
pick(array)
shuffle(array)
fork(label)
```

要求：

```text
相同种子产生相同结果
不同种子能够产生不同结果
地图、资源、技能分别使用子随机流
资源抽取不能改变地图结果
技能抽取不能改变地形结果
```

建议子流：

```text
map
terrain
resource
skill
ai
cosmetic
```

表现层随机数不得影响权威规则随机序列。
