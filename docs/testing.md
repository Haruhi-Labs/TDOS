# 测试与验收

测试用于证明改动满足行为契约。先运行能够暴露本次问题的检查，再按受影响边界扩展；发布候选另有完整门禁。命令定义以 [package.json](../package.json) 为准。

## 可执行分层

| 命令 | 覆盖 | 不代表什么 |
| --- | --- | --- |
| `npm run check:static` | 相对导入、已声明的依赖边界、循环依赖、单人/联机绘制副本守卫 | 不证明运行时行为或完整架构正确 |
| `npm run test:logic` | 规则/AI/教程、协议、权威回放、插值、房间/运行时模块、统计存储、票据验签和表现辅助函数 | 不运行浏览器或真实远程服务 |
| `npm run test:browser` | Chromium 中的更新日志、统计、身份、交互、WebGL 和测试服隔离场景 | 不证明真实账号登录、物理移动设备或生产可用 |
| `npm run test:integration` | 本地真实 WebSocket 服务的协议、容量门禁、版本和公开字段隔离 | 不证明生产容量或部署成功 |
| `npm run test:ai:simulation` | 18 局固定种子的 AI 对抗回归 | 不证明所有阵容平衡 |
| `npm run test:all` | 以上各层的完整回归 | 不包含生产构建、独立容量压测或人工验收 |
| `npm run build` | 模块/表现守卫与 Vite 生产构建 | 不替代行为测试或浏览器验收 |

既有细分命令保留。`test:ui:cooldown`、`test:ui:koizumi` 和 `test:mobile:scout` 实际是 Node 逻辑/绘制调用检查，归入 `test:logic`，不能因名称含 UI/mobile 就算浏览器或真机证据。

`test:core:bunny-haruhi` 验证兔女郎春日配置、独立注册与状态、形态序列、倍率、资源边界、舞台和伴随舰生命周期，默认随 `test:core` 执行。全部采用内存夹具，不连接服务或读写身份/统计存储；单独通过不代表界面及多端验收。调用合同见[兔女郎春日规则](bunny-haruhi-rules.md)。

`test:core:rng` 验证对局随机源：种子序列、子流独立、环境模式随全局随机源替换即时生效，以及带种子的对局不依赖全局状态即可逐帧复现。`test:core:ai-observation` 验证 AI 观测层：观测可 JSON 往返、视野外敌舰的实体与坐标不进入观测、雷达接触保留带误差的位置、猎杀标记只暴露编号与位置、越过迷雾的读取只有 `privileged` 中的四项，以及 AI 门面在外部调用时刷新观测。`test:core:ai-actions` 验证 AI 动作层：扩展侦察动作不能通过对局动作协议校验、端口在动作提交后重建观测、标准执行链下禁控期间的换挡被拒绝并计数、旧路径仅供对照。`test:core:ai-params` 验证 AI 参数层：参数是可 JSON 往返的纯数据且解析结果深冻结、四档难度的覆盖层与让分表、`legacy` 预设、未知键与类型不符的覆盖被拒绝、让分由对局写入舰队，以及每个参数分节各改一项后带种子的对局结果确实改变。`test:core:ai-policy` 验证 AI 策略层：每个角色都有档案、档案里的施放条件与瞄准可以只用纯数据夹具测试、规则策略不经对外门面也能凭端口独立运行且不持有对局或舰队对象。五者都使用内存模拟，默认随 `test:core` 执行。

`test:core:haruhi-support` 单独验证支援抽取及调度的随机次序、消费次数、旧状态结构、副舰来源隔离和封印恢复，不启动外部服务，默认随 `test:core` 执行。`test:api` 同时锁定 `haruhi-flagship.js` 的全部旧导出；副舰适配通过不等于新来源已接入实际战斗。

`test:core:bunny-haruhi-integration` 验证正常阵容入口、舞台和变身的实际接入：资源支付/持续积分、广播、入场禁控与移动后开火顺序、驱散、锁档、支援来源、破盾共用冷却、白名单快照及伪造动作拒绝。330tick新角色场景同时比较直接输入与服务端队列，并验证每帧快照差量往返。全部采用内存模拟，不启动服务；默认随 `test:core` 执行。阿虚实体由下述专项验证，前端展示另行验收。

`test:core:bunny-companion` 验证阿虚实际生成、难度派生、独立资源/编队/碰撞、操控拒绝、跟随、胜负与舰损排除，再验证20/6秒自动技能、独立驱散、封印/沉默与死亡清理，最后覆盖5秒临时策反、双伴随舰、反策反、母舰伤害保护、光线计数、猫爪/碰撞/弹体和当前阵营伤害归属。900tick直接输入/服务端队列逐帧一致并经过量化差量往返；换队显示缓存与插值不写回模拟。使用内存模拟，不连接服务或读取身份/统计目录，默认随 `test:core` 执行；不代表专属美术、真实浏览器及多端验收。

`test:camera` 在 Node 中验证导演镜头的鼠标锚点、反向接管、阻尼平移、30/60/144Hz响应一致性、边界、复位及减少动态效果偏好；同时检查玩家模式仍使用原即时缩放。它不代表实际浏览器手感或物理设备验收。

`test:ui:resolution` 验证单人、联机和观战的高 DPR 与 4K/5K 视口：实际 GPU 缓冲匹配设备像素，布局变化和跨屏密度变化会重分配，取景不变且卸载停止观察。另对 WebGL1/2 八倍文字与 Canvas 原生文字逐像素比较，并验证字形预热复用、缓存预算、提交前保护与曲线误差；倒计时专项逐帧核对三个渲染后端的 3、2、1 像素中心，并检查正常零边距及缺少字形度量时的字号兜底。它自建回环前端，联机 WebSocket、身份和统计均使用夹具，不连接已有服务；可用 `RESOLUTION_SCREENSHOT_DIR` 保存字形像素图。软件 GPU 和模拟屏幕不能替代物理高分辨率屏幕的画质及帧率验收。

`test:ui:spectator` 自建回环 WebSocket 服务与临时统计目录，以两位玩家和 Chromium 观众验证进入前双方昵称、首快照前阵容、实时冷却、六个技能名的悬浮/键盘/点按说明与视口边界、九种视口、逐帧平滑滚轮、拖拽取消、退出、玩家模式恢复及新版联机舰况入口的分离/切舰；身份接口使用游客夹具。移动端检查页面与展板均不滚动、六舰姓名完整及地图利用剩余空间，另用粗指针手机/平板验证触屏说明与退出不发送战斗指令。异常技能状态与零能量另用构造数据验证。可设置 `SPECTATOR_SCREENSHOT_DIR` 保存画面、`SPECTATOR_VIDEO_DIR` 保存交互录像，仍不代表远程多端或物理设备验收。

`test:ui:tournament` 自建回环 WebSocket 和 Vite 服务，使用临时统计目录、游客身份夹具与四个独立浏览器连接。验证空比赛房的独立观战、主持不占选手席位、真实换阵容取消就绪、双方就绪不自动开始、伪造主持/选手请求拒绝、3 秒静止倒计时、阵容锁定、选手/观众开赛界面切换和主持断连回收；覆盖八种桌面/窄屏视口及粗指针手机/平板。`test:server:rooms` 另覆盖等待时离房补位、撤回就绪、旧客户端能力、私房口令隔离及开赛容量边界。可设置 `TOURNAMENT_SCREENSHOT_DIR` 保存画面；这些证据不代表远程多端、真实赛事或物理触屏验收。

`test:ui:command` 启动回环前端并夹具化身份/统计接口，验证真实单人对战的分离、切舰、换挡、键盘帮助、技能施放后的冷却与状态出现，以及五种视口；另用权威快照夹具覆盖技能冷却、沉默、瞄准、被动技能及编队零能量。状态浮层交互与说明内容统一由 `test:ui:status` 覆盖，操作台不重复执行悬停文案断言。可设置 `COMMAND_SCREENSHOT_DIR` 保存画面，不代表联机延迟或物理触屏验收。

`test:ui:skills` 是选角技能分层介绍的专项检查：既有中文文案保持一致，新角色用简介和完整可滚动详情分层展示，详细参数核对技能元数据和关键倍率；Chromium 覆盖九角色十八技能、桌面与触屏布局、中英日内容、入口定位、键盘激活与非模态焦点、外部点按/Esc 关闭、退出清理及矮屏滚动。追加 `-- --character=bunny_haruhi` 可只复测该角色的浏览器场景。它自建回环前端，身份和统计接口使用夹具，可设置 `SKILL_DETAILS_SCREENSHOT_DIR` 保存画面；物理触屏仍需人工验收。

`test:ui:selection` 检查眩晕和冲击禁控期间的选舰保持、操作无效、解除后的原舰恢复与击沉切舰。Node 直接核对共享模拟拒绝禁控动作；Chromium 覆盖单人/联机、桌面/触屏和主副舰。它自建回环前端，身份与统计使用夹具，单人模拟仅通过测试插件注入状态，联机 WebSocket 完全由快照夹具接管；不连接现有联机服务，不代表真实网络延迟与物理设备验收。

`test:ui:status` 是角色卡状态专项：Node 验证完整目录、权威寿命、净化/涤除、续期、叠层、死亡及显示不写回；Chromium 用权威模拟快照验证桌面对战/观战一致、绿红边框、时间环、禁用选舰仍可查看效果、悬停/键盘/点击、移动端隐藏、六种视口的空栏与状态变化布局稳定及卸载。自建回环前端，身份与统计使用夹具，可设置 `STATUS_EFFECT_SCREENSHOT_DIR` 保存画面。真实单人技能由 `test:ui:command` 补充，本地 WebSocket 收发由 `test:ui:spectator` 补充；不代表物理设备或远程网络验收。

`test:all` 按静态、逻辑、AI 模拟、浏览器、网络集成顺序执行，首个失败即停止。后续未执行项目应明确标注；修复后先重跑失败及受影响检查，发布前补齐完整候选结果。

## 按改动选择

下表是最低相关证据的选择入口，不要求每次把所有行执行一遍。跨边界改动取相关项并集；缺陷复现还应增加针对性断言。

| 改动 | 相关检查 | 额外验收 |
| --- | --- | --- |
| 纯开发文档 | `git diff --check`，核对本地链接、路径、npm 命令 | 不要求游戏构建或浏览器；修改测试编排需展开核对成员并实际运行 |
| 提交规范或 CI 门禁 | `test:commits`、`check:commits -- --range <基线> HEAD`；工作流改动检查 YAML/Actions 语法 | 验证拒绝不合规标题、中间提交及合并消息；格式校验不能证明工作项划分正确 |
| 模块拆分、导入或稳定导出 | `check:static`、`test:api`、受影响模块测试、构建 | 跨页面生命周期改动检查挂载与卸载 |
| 规则、角色数值、AI、教程 | 对应 `test:core:rules` / `test:core:ai` / `test:core:tutorial`；权威行为加 `test:authority`、`test:ruleset`，AI 加 `test:ai:simulation`；构建 | 规则语义变化更新版本；检查受影响技能和模式，模拟统计不替代平衡判断 |
| 动作、固定时钟、服务端执行链 | `test:actions`、`test:authority`、`test:server:runtime`，协议变化加 `test:ruleset`、`test:network:guards`；构建 | 真实多客户端输入、倒计时、结算及退出 |
| 快照、房间、网络协议 | `test:network`、`test:online:components`、`test:server:rooms`、`test:server:runtime`、`test:network:guards`；构建 | 断连、观战、乱序/恢复；容量参数变化另做隔离压测 |
| 插值或联机显示 | `test:online:state`、`test:online:components`；构建 | 延迟下的移动、换挡与航线确认，显示不得写回模拟 |
| 战场视觉或 WebGL | `check:static`、`test:ui:webgl`，古泉效果加 `test:ui:koizumi`；构建 | 单人/联机/观战受影响画面、WebGL1/2 及失效回退 |
| 普通页面、移动交互 | 对应 `test:ui:interaction` / `test:ui:command` / `test:ui:skills` / `test:mobile:scout` / `test:ui:cooldown`；构建 | 受影响桌面/窄屏路径；无现成测试时直接验证实际页面 |
| 更新日志或多语言内容 | `test:changelog`、`test:ui:changelog`；构建 | 非日志页面翻译另查实际页面，日志测试不覆盖全部词典 |
| 身份链路 | `test:identity`、`test:ui:identity`，服务端接入变化加 `test:network:guards`；构建 | 修改 SSO 流程时使用隔离身份环境走真实登录及游客降级 |
| 统计采集、存储或榜单 | `test:statistics`、`test:network:guards`，页面变化加 `test:ui:statistics`；构建 | 去重、跨版本隔离、热更新同桶、旧记录恢复、公开字段及一次性上报 |
| 发布流程与版本 | `test:release`、`test:changelog`；涉及测试隔离加 `test:ui:staging`、`test:online:components` | 检查择取来源、额外改动拒绝、发版/热更新差异；CI 与服务器配置需另行实际验证 |
| 发布候选 | `test:all`、目标基路径构建、受影响页面回归 | [运维门禁](operations.md)及上线后实测 |

表中缩写均使用 `npm run <命令>`。日常通过针对性验证即可交付；共享入口大改、影响范围无法可靠界定时扩大到 `test:all`。

## 测试环境与运行边界

`test:ui:bunny-haruhi` 随浏览器层执行，验证权威摘要、差量与插值、三语单人/联机/观战HUD、桌面/窄屏锁档与舰况、附着、免伤到期、阿虚死亡、终局、原皮占位、迷雾、主图/小地图几何、WebGL2/WebGL1/Canvas2D及 `/game/` 素材缓存；验证404不逐帧重试及预热后提交/字形缓存稳定。自建回环Vite，API与WebSocket均由本地夹具接管，不访问现有游戏/身份/统计服务。设置 `BUNNY_VIEW_SCREENSHOT_DIR` 可保存截图和 `render-stats.json`。

`test:core:bunny-ai` 随核心层执行，验证显式主副舰阵容、形态决策、雾中情报边界及旧随机AI池的顺序/消费。`test:server:rooms` 和 `test:network:guards` 覆盖新角色房间的规则声明门禁；`test:statistics` 覆盖新旧春日独立归档、伴随舰阵容排除及重启恢复。

`test:ai:bunny-haruhi` 为按需离线平衡采样，不加入 `test:all`：11种自然开局场景和2种明示条件开局，每种3个固定seed、双方换边及新旧阵容，单局战斗上限180秒。可用 `-- --scenarios=stage-edge,stage-kite` 定向重测。实际治疗/自损、阶段时间、支援伤害、伴随舰寿命及策反计数写入 `bench/bunny-haruhi-acceptance/balance*.json`，不连接服务。条件开局的停战准备期不计入战斗时长/治疗统计，胜率必须与自然开局分开说明。

`test:perf:bunny-haruhi` 从本地Git只读提取 `3d7f6a1` 到临时目录，同机独立进程交替五轮，比较旧阵容及双伴随舰/全部支援压力场景的tick中位数、p95、最大值和快照字节。输出 `performance.json`，结束清理自身临时目录，不使用线上服务；它是按需测量，不加入默认回归。5%为建议回归线，超过时必须如实报告，不修改阈值或反复运行挑选结果。

- 从仓库根目录运行，依赖安装见[开发约定](development.md)。浏览器层需要 Playwright Chromium；缺少时运行 `npx playwright install chromium`。仅运行逻辑层无需安装浏览器。
- 浏览器脚本通常自建回环地址 Vite 服务，并对部分接口使用夹具。Vite 仍含本地 API/WS 代理，所以不要把整套测试描述为完全离线或绝无外部访问。
- `test:ui:interaction` 读取 `HARUHI_PREVIEW_URL`，会操作目标页面。普通本地回归保持该变量未设置；只有测试目标明确且已授权时才覆盖。
- `test:network:guards` 自启本地服务并使用临时统计目录；`test:statistics` 使用临时存储和构造记录。它们不会证明真实身份数据库迁移或线上持久目录权限正确。
- 本地服务测试继承部分进程环境，不要从加载生产凭据的 shell 启动测试。清理仅限本次启动的进程和临时目录。
- `test:online:state` 包含7.5Hz观战短特效删除补帧与寿命边界；`test:ui:webgl` 按效果关闭前后的像素差检查观战双方扫线、非选中舰航线和共享技能表现，覆盖 WebGL2、WebGL1 与 Canvas2D。
- WebGL 用像素、绘制调用、回退和帧耗时检查；航线专项核对 WebGL2、WebGL1 与 Canvas2D 中观战隐藏终点及曲度手柄、对战保留手柄。观战界面专项同时检查桌面矮屏与移动端的一屏六舰、固定状态栏和地图最大正方形，并覆盖六舰同时受控且显示冷却的矮屏组合。记录运行环境，不把某台机器上的相对性能通过当作所有 GPU 的帧率保证。

独立容量测试默认自启本地服务：

```bash
env -u NETWORK_WS_URL npm run test:network:load
```

可用 `NETWORK_ROOMS`、`NETWORK_SPECTATORS_PER_ROOM`、`NETWORK_DURATION_SECONDS` 调整负载；`NETWORK_WS_URL` 会把流量送到指定服务，只有在目标及压测影响已经授权时使用。容量压测和 `test:ai:shamisen` 专项平衡模拟均不在 `test:all` 中。

## 测试质量与失败处理

- 断言可观察行为和边界：例如同动作逐 tick 一致、非法输入被拒绝、统计不进入快照、游客失败回退可用。避免只断言源码含某段实现文字；现有源码守卫只证明它明确检查的结构。
- 修复缺陷时保留最小复现；新增逻辑覆盖正常与关键失败/边界输入。固定种子和临时夹具使失败可复现，避免仅用等待时长猜测页面就绪。
- 区分代码回归、原有失败与环境缺失。保存失败命令和首个有用错误；修复本次问题后重跑相关项，不无限重试掩盖不稳定性。
- 业务契约确实改变时同步更新实现与预期并解释原因；不能只删断言、提高超时、放宽性能阈值或重刷基准使测试变绿。
- 浏览器自动化、人工视觉检查、真实多客户端/账号及上线验收分别记录。夹具通过不代替真实链路证据。

交付记录通常只需“检查命令与结果、额外场景、未覆盖项及原因”。发布或性能问题再附提交、基路径、环境和产物证据，无需为每次小改动创建永久报告文件。

## 架构重构行为基线

`npm run test:architecture:replay` 使用同步远端后的重构起点 `406c910` 录制的固定种子基线，覆盖含兔女郎春日在内的九组阵容、四种难度、每组 3600 帧。每帧将完整公开权威状态与 AI 调试决策纳入摘要，每 300 帧比较一次，失败时定位首个分歧区间。它自建内存模拟，不连接服务、不写统计。基线只在明确评估规则变化后通过 `node scripts/verify-architecture-replay.mjs --record` 更新；纯架构重构不得重刷基线来接受行为变化。它补充领域断言，不证明所有技能组合、真实设备或线上行为。

`npm run test:architecture` 检查可替换角色能力、查询无副作用、快照/观察可写引用隔离及抓痕到期生命周期。联机组件测试另外断言只读传输视图与深冻结快照；房间测试验证序列化纯度、显式连接整理及阵容/结果副本。它们与逐帧基线互补：行为不漂移之外，还要确认新边界实际限制了写入。

`node scripts/measure-architecture-performance.mjs` 是按需的重构前后性能对照：从行为基线提交只读提取代码，复用普通战斗与全部支援压力夹具，在独立进程中交替测量五轮，同时核对最终权威摘要和快照字节。结果写入被忽略的 `bench/architecture-acceptance/performance.json`。测量范围为模拟 tick，不覆盖渲染、收包和每帧序列化；超过 5% 建议线应如实分析，不通过改阈值或挑选轮次掩盖。

## 架构边界专项

- `test:architecture`：纯选敌读模型、能力替换、查询无副作用、快照引用隔离、碰撞实时几何与接触历史、任务输入复制、策反集合归属、技能失败退款和效果顺序。它验证受限接口的行为，不把模块没有循环导入等同于语义解耦。
- `test:server:stream`：无真实 socket 的确定性会话测试，验证内部基线不可访问、非法 ACK 拒绝、全量/差量还原、补帧、握手升级、降频与重置。与 `test:server:runtime`、真实回环 `test:network:guards` 互补，已加入 `test:logic`。
- `test:solo:session`：无 DOM 的本地会话测试，验证权威对象不外泄、帧间即时输入、冻结快照复用、插值不回写、暂停、追帧上限与重开，已加入 `test:logic`。浏览器单人状态夹具只在测试 Vite 插件中取得模拟并显式使缓存失效，生产代码没有调试后门。
- `node scripts/measure-solo-session.mjs`：按需离线对照原始 dev 基线和当前单人帧管线，独立进程交替五轮，各 1,800 个 60Hz 显示帧；逐帧比较权威及插值结果，计时包含模拟、序列化和插值，排除摘要计算、DOM、Canvas 与 GPU。保留混合帧指标，并额外按权威时间是否推进分类记录模拟帧、仅插值帧和结束帧的数量、中位数、p95、均值及总耗时；分类在计时区间外，不能替换原指标。结果连同 CPU、Git 提交和前后负载保存在忽略目录 `bench/architecture-acceptance/solo-session-performance.json`。5% 是建议线，超过时保留结果并解释，不改阈值或重刷行为基线。

`test:ui:result` 自建回环前端并夹具化 API/WebSocket，覆盖玩家/观战、桌面/触屏的胜者和双侧阵容、重复终局不重建视图、关闭倒计时与返回大厅清理。它已加入浏览器门禁；不会连接现有游戏、身份或统计服务。

`test:architecture` 通过 `verify-character-boundaries.mjs` 追加角色内部边界检查：九角色轮换主副舰的重复只读查询、基础移动/属性/射击的能力替换、命中扩展与基础承伤顺序、投影不推进生命周期、侦察机出生采样与策反能力保持、专属变身与普通技能成功提交次数，以及破盾资格和消费失败。使用内存对局，不访问身份/统计存储或外部服务；它不证明全部角色状态已经私有，也不替代原基线回放及真实页面验收。

角色生命周期边界检查随 `test:architecture` 执行：`verify-beam-lifecycle`、`verify-future-form`、`verify-sponsor-effect`、`verify-bunny-ownership`、`verify-support-ownership` 分别验证光线固定命中集合/恰好一次、形态先提交再换算、赞助同帧保护、伴随关系事务及支援嵌套集合的只读边界。它们是离线行为与写权限检查，不替代原 dev 回放、浏览器或性能对照。

`verify-bunny-ownership` 还验证舞台样本不可外部覆写、历史投影隔离、来源死亡清理、持续结算游标不公开、重复初始化与采样不重复治疗，以及不同对局的时钟隔离。

`verify-fleet-participation` 随 `test:architecture` 验证编队与胜负资格分别可替换，生命比例和猎杀候选消费相同胜负资格，无猎杀候选时不消耗随机数；原核心伴随舰测试继续覆盖旧额外舰船、伤害分摊及舰损的兼容语义。

`verify-plain-data` 随 `test:architecture` 校验深层复制、嵌套冻结、历史节点复用及 `__proto__` 普通数据键。修改公共数据遍历时同步检查单人会话、房间输入、快照流和差量消费者，并保留性能优化前的样本，不以取消只读边界降低开销。

`verify-projectile-phase` 随架构检查验证弹体创建载荷隔离、拦截先于移动、活集合迭代与清除死亡弹体后再收尾。古泉护盾与春日支援的实际优先级、命中及恢复继续由核心测试和原基线回放覆盖。

`verify-hero-power-ownership` 覆盖勇者之力私有事件队列、嵌套命中编号只读、历史视图、单次释放、快照别名隔离和施法者死亡取消；范围命中、友敌飞行器清理及控制恢复继续保留核心规则断言。

`verify-feedback-ownership` 覆盖护盾表现独立限频、不额外消费编号、历史视图与快照隔离，以及死亡反馈先于随机重选、表现寿命不影响规则。勇者之力属于战斗事件，不能放入仅负责表现寿命的反馈队列。


`verify-expanding-wave` 与 `verify-throttle-constraint` 随架构专项执行：前者验证共享几何脱离技能状态后的载荷与覆盖边界；后者验证基础运动所有者的存储、读写约束差异，以及兔女郎封印解除和锁档到期。角色来源仍由核心行为测试及原 dev 回放覆盖，不能只以可替换接口测试代替实际技能回归。

`verify-ai-debug-projection` 随架构专项验证策略计划、动态决策与侦察方案的嵌套引用隔离，覆盖消费方修改和策略后续修改两个方向。优化序列化复制范围时仍需原始回放与单人完整帧性能对照。

`verify-character-configuration` 随架构专项验证九角色的共享定义、阵容及出生身份不可改写；自定义机体、训练配置与对外投影没有反向写入引用。教程训练仍经舰体操作替换配置，普通战斗和教程行为由核心与原始回放继续验证。

`verify-character-localization` 覆盖三语言、九角色的只读展示投影与战场技能名称，确认切换语言不会改写共享定义、已有对局或新建对局的权威快照；技能浏览器专项另外核对桌面和移动端的角色名称及定位文案。

`verify-claw-ownership` 验证抓痕的只读状态、历史视图隔离、来源切换、到期查询不提交，以及爆发清零先于承伤。核心和状态栏夹具通过 `registerClawHit` 建立层数，不直接覆盖组件；净化、免控和真实弹体四层爆发的原有断言继续保留。


`verify-haruhi-flagship-runtime` 覆盖强化寿命私有化、同帧保护、解锁先于运动换算、续期不重乘及净化保留常驻支援。`verify-vision-wave-phase` 覆盖四组双边目标先采样、独立只读句柄、伪造句柄与错误所有者拒绝、净化顺序、有效反馈和可替换端口；同时用真实朝仓镜像对局防止先结算一席吞掉另一席命中。两项随 `test:architecture` 执行。

AI 测试场景在测试侧投影实体；生产策略拒绝实体和能力回调。长局统计也消费雷达投影。`golden-trace` 不再支持旧的 `--action-mode` 旁路；行为对照使用固定旧提交，不能在生产端口重新开放旧路径。性能脚本对旧 Git 基线的字段装配兼容仅存在于离线夹具。


内部残留边界检查随 `test:architecture` 执行：`verify-ai-memory-ownership` 验证情报入队复制、反应延迟、不可变接触、过期淘汰、概率输出隔离，以及侦察计划缓存和重编组时钟；`verify-targeting-ownership` 验证感知样本只读、历史隔离、集火预算、目标死亡后的重新选择和猎杀优先级。导航专项额外拒绝端口属性写入，施放专项验证专属结果的冷却→统计→显形→视野刷新顺序。场景所需可见性由测试侧隔离传感器输入并运行真实采样生成，不恢复生产可见集写入口；情报老化使用时间推进，不篡改记忆时间戳。

本轮角色复查专项继续随既有门禁执行：

- `test:core:ai-policy` 拒绝角色事实中夹带执行端口或策略计时器，检查嵌套输入与档案注册表不可变，并保留无穷距离的判断语义。
- `verify-support-ownership` 拒绝将读快照或普通对象作为写入来源；验证解锁、封印恢复、变身和同帧追帧回调不会污染历史快照，也不会遗留过时缓存。
- `verify-bunny-ownership` 确认 Team 不再承载伴随舰生成及战区策反事务；既有核心场景继续覆盖临时策反、归还、反策反和成员集合。
- `verify-ai-skill-ownership` 验证技能时钟私有、决策嵌套别名隔离、施放后读取新冷却，以及只返回破盾重规划结果；真实 AI 破盾场景继续验证同帧路线行为。`verify-ai-debug-projection` 通过真实技能推进验证历史输出，不再覆写私有决策构造夹具。

以上使用内存对局，无外部读写；与原始逐帧基线、AI 长局及浏览器验收互补。
